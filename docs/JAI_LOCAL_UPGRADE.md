# JAI local assistant upgrade

The assistant keeps the existing fast scheduling handlers and adds a local conversational fallback. Ollama is the only model called by the chat. The deployed environment retains `JADWAI_AI_ENABLED=true` and `JADWAI_AI_PROVIDER=local`.

## Capability coverage

The fallback discovers the application's effective API routes, including included routers, instead of maintaining another hand-written list of operations. A regression check compares the catalogue with OpenAPI. It covers academic records, course setup, advising students, semester configuration, accounts, constraints, assignment locks, schedules, comparisons, exams, exports, proposals and evaluation tools.

Authentication/credential entry stays in the account UI. File selection stays in the import UI. Human evaluation judgments must come from the administrator. A route being available does not prove that a small model will interpret every phrasing correctly.

For unfamiliar requests, the model chooses an existing operation or answers conversationally. It then receives that operation's actual input schema and asks for missing details or proposes one complete request. Request validation runs before confirmation; database references, permissions and business rules are checked again by the existing endpoint. Mutations use the version from the proposal. PUT updates preserve omitted existing fields. Confirm with the button or an explicit reply such as "yes, do it"; "cancel" rejects the latest proposal.

Chat history and pending clarification state persist per chat. Explanation requests are treated as discussion. The local prompt uses bounded history and relevant context; conceptual discussion omits unrelated records and renders session times as clock strings.

## Multipart scheduling

A coordinator runs in the API process with API database credentials. It advances completed builds every two seconds without browser traffic. Workspace locking prevents duplicate continuation. Active jobs, cancellation, changed inputs and failed validation stop continuation. Restarting the API resumes eligible saved chains. The API and solver worker must remain running; closing the browser is safe. No worker privilege expansion is needed.

## Constraint output

The local adapter bounds output tokens and gives semantically invalid output one validator-guided correction attempt. The caller timeout bounds the whole operation. Independent proposal validation remains authoritative; invalid output cannot become approved rules.

## Verification and limits

Tests cover API coverage, invalid proposals, clarification persistence, no mutation before confirmation, typed confirmation, secret-free summaries and continuation without HTTP polling. `scripts/check_jai_local.py` checks two non-mutating live-model conversations with synthetic context.

The historical local-model run has 116 saved responses, not a completed 144-case evaluation. Old predictions are preserved. Accuracy and latency need remeasurement for the upgraded pipeline on reviewed data. Human annotations cannot be generated by JAI and counted as human review. CPU inference remains hardware-bound. Do not claim parity with a frontier model or universal correctness.
