## Completed first checkpoint

`backend/app/extraction.py` defines an interchangeable asynchronous provider interface and an explicitly named deterministic test double. It has no HTTP route, database access or rule-approval action. It accepts original text, a serialized context snapshot, input version and prompt/schema versions. Its hash binds all those fields; later mutation of the caller's context cannot alter the request.

Transport results retain provider/model identifiers, the input hash/version, attempts and observed per-attempt elapsed time. Strict JSON parsing rejects duplicate keys, nonfinite values, oversized responses and non-object output. A JSON object is only a candidate: schema, decision consistency, real-entity and calendar validation remain required. No candidate is marked approved.

Only explicitly transient failures and timeouts are retried, under an explicit limit of at most three retries. Invalid responses and permanent errors are not silently repaired or retried. Provider exception messages are not exposed in results. Caller cancellation propagates. Timeouts require cancellation-cooperative adapters and eventual provider SDK timeouts; this is not a kill switch for arbitrary blocking or cancellation-suppressing code. Raw bounded responses remain private in-memory data for later persistence design; they are not logged by this module.

Validation: 15 focused backend tests pass, covering immutable context snapshots, source binding, strict JSON failures, retries, timeout, permanent-error redaction, cancellation and invalid execution policy. These are synthetic software tests, not model-performance measurements. No paid calls were made.
